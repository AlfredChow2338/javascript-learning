# 如何解決 AI 生成代碼混亂

AI 生成代碼「亂」的根因不是模型笨，而是 **優化目標是「這段能跑、看起來完整」**，不是 **repo 邊界、資料協議、可維護性**。權限從補全 → 對話 → **全權 agent** 越往後，越需要 **先約束、再規劃、再切片實作、最後機械驗收** — 否則會得到大量互不相容的局部最優。

### 本質一：三階段與權限邊界

- **Copilot 時代**：行級補全 — 人仍握架構與檔案邊界。
- **Chatbot 時代**：多檔上下文 — 亂開始於 **跨檔命名、重複 util、風格不一致**。
- **Vibe / Agent 時代**：可改整棵樹 — 若無 **全局規則 + Plan 只讀 + CI 閘門**，會快速堆出「能 demo、難演進」的程式。
- **取捨**：自動化越高，**規範與驗收** 越要前置，不能等 PR 才人工掃。

### 本質二：為什麼會亂（因果）

- **無頂層協議**：表格、協同、公式各寫各的資料形狀 — 改一處崩一片。
- **無切片**：一 prompt 做登入 + 渲染 + CRDT + Worker — AI 用 placeholder 糊過去。
- **無硬約束**：eslint / tsc / prettier 只「建議」— 風格與型別債務進 repo。
- **無驗收標準**：頁面能點 ≠ 邊界、性能、安全覆蓋（審核維度見 `ai/2-怎樣審核驗收AI代碼.md`）。

### 本質三：預防 — 約束先於生成

- **開發手冊 / Rules**：`.cursorrules`、`CLAUDE.md` — 寫清 **只能** 與 **禁止**（目錄結構、狀態放哪、禁止無關重構）。
- **工具當法律**：ESLint、TSConfig、Prettier、test **必過 CI** — AI 產出與人寫同一標準。
- **頂層資料協議**：先定 **domain model / API 契約 / 事件格式**（例如協同層傳什麼、表格 cell 唯一 id）— 再允許寫 UI；複雜域 **沉 monorepo 子包**，頁面只組裝。
- **誤解**：規則寫得越長越好 — 有效的是 **可執行、可 lint 的少數硬規則**，不是 README 散文。

### 本質四：Plan 先於 Implement

- **STAR-L 式規劃**（可對應 `.plan` / Plan mode）：
  - **S**：需求與非目標（不做什麼）
  - **T**：方案對比與選型（為什麼用 yjs / 虛擬列表）
  - **A**：實施步驟與檔案邊界
  - **R**：風險 — 性能瓶頸（千萬行、公式重算）、協同衝突
  - **L**：驗收與優化指標
- **機制**：Plan **只讀** — 先出步驟與驗收矩陣，再開寫碼；避免邊做邊改架構。
- **`.features` 切片**：按 **垂直特性** 逐步交付（例：先表格渲染引擎包 → 公式 Worker → 協同協議 → 登入殼），每片一 PR，禁止單次 PR 跨三個子系統。

### 本質五：複雜專案怎麼切（以協作表格類為例）

- **性能**：大表 = **虛擬滾動 + 穩定 key + 分頁**；重公式 = **Web Worker**，主線程只接結果。
- **協同**：CRDT/OT（如 yjs）**獨立層** — 傳輸協議、服務端、UI 三分；勿在 React 元件裡直寫算法。
- **界面**：登入、殼、路由 **薄** — 依賴子包公開 API，不複製引擎邏輯。
- **為什麼**：AI 擅長「接線」；**引擎與協議** 需人定邊界，AI 在邊界內填實現。

### 本質六：Vibe Coding SOP（生成後仍要閘門）

1. **Spec / Plan** — 需求 + 驗收矩陣
2. **按 feature 生成** — 小 diff
3. **測試** — unit / 關鍵 integration
4. **lint + tsc + CI**
5. **Audit** — 可用 / 待改 / 風險無效（流程見 `ai/3如何用claude-code-agentic工作流做AI代碼量化驗收.md`）

- **MCP / Skill**：把「查文檔、拉元件、跑 audit」變 **固定協議**，少靠每次口頭 prompt。
- **禁止**：AI 初稿 **未 audit 直上 prod**。

### 與審核驗收筆記的關係

- **本篇**：**上游防亂** — 規則、協議、Plan、feature 切片、子包邊界。
- **`ai/2-怎樣審核驗收AI代碼.md`**：**下游驗什麼** — 七層、七指標、高危模組。
- **`ai/3如何用claude-code-agentic工作流做AI代碼量化驗收.md`**：**怎麼自動跑驗收** — Plan → Implement → Audit → Triage。

### 小結

- **問題**：Agent 權限大，局部可跑 ≠ 架構一致、可演進。
- **手段**：硬規則 + 頂層協議 + Plan 只讀 + feature 切片 + 沉底子包 + SOP 與 CI/MCP。
- **結果**：AI 產出落在 **既定邊界內**；亂的部分在 Plan 與 audit 階段被攔下，而非 merge 後才還債。
