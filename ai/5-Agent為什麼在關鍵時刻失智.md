# Agent 為什麼在關鍵時刻失智

客服 Agent 演示完美、上線亂退款；AutoGPT 寫報告跑到無關八卦；行程 Agent 忽略帶幼兒與老人卻訂紅眼航班——這類「關鍵時刻失智」多半不是模型不夠強、RAG 不準或 Prompt 不夠長，而是 **規劃與推理模組的架構失效**（業界調查約八成故障落在此）。換 GPT-4o、優化 RAG、改幾十版 Prompt 只能緩解，**不能根治**。

### 邊界：什麼時候才談「規劃失智」

- **適用**：開放域、多約束、多步工具調用的 **通用 Agent**（行程規劃、長報告、複雜客服流程）。
- **不適用**：封閉域固定流程（符號規劃可 100%）、單步問答／文案（不需規劃，原生 LLM 夠用）。
- **與本系列前幾篇的關係**：`1–3` 管 **代碼怎麼寫、怎麼驗收**；本篇管 **多步 Agent 為什麼在執行中段邏輯崩** — 驗收再嚴也救不了規劃從根錯。

### 本質一：Agent 架構與規劃的本質

- **標準迴圈**：感知 → **規劃** → 行動 → 反饋；失智常發在 **規劃／推理**，不是感知或單次 tool call。
- **規劃**：在狀態空間裡搜一條從初始到目標的可行路徑（可建模為 MDP）；目標是累積獎勵期望最大。
- **推理**：路徑搜尋中的 **約束是否滿足、動作是否推進目標** — 演繹（規則→結論）、歸納、溯因；LLM 預設偏 **機率關聯**，不是邏輯演繹。

### 本質二：五個底層困境（問題 → 機制 → 後果）

**1. 狀態空間爆炸**

- 開放任務狀態數隨約束 **指數成長**（n 個約束 → O(2^n) 量級組合）。
- CoT / ReAct / ToT / RAP 在約束 >7 時成功率陡降 — 啟發式剪枝跟不上。
- **機制**：Transformer **自回歸、無全局狀態視圖**，易陷局部最優（省機票卻選凌晨班）。
- **後果**：約束一多就「撿芝麻丟西瓜」。

**2. 隱式約束漏檢**

- 用戶只說顯式條件（預算 1 萬）；**隱式常識**（帶 2 歲幼兒 → 不坐紅眼、要嬰兒床）靠模型自己推。
- 統計上約 **六成規劃錯誤** 來自隱式約束未觸發。
- **機制**：P(隱式|顯式) 在訓練共現低 → 被忽略；很多架構 **根本沒有「隱式約束推理」這一層**。
- **後果**：計畫表面合理、實際違反常識。

**3. 長任務上下文衰減**

- 超過 ~10 步，早期目標與約束被擠出 **有效注意力** — 寫 12 章大綱寫到第 7 章就忘格式要求。
- 實測：不論 4k / 32k / 128k，步數 >20 時 **核心約束保持率常掉到 ~40%**。
- **機制**：距離當前 token 越遠，attention 權重越趨近零 — **不是單純把 context 窗口拉大就能解**。
- **後果**：長鏈任務後段「失憶式」偏離。

**4. 工具調用因果偏差**

- 典型錯：**順序顛倒**（先訂票再查票）、**缺前置**（沒取公式就算淨利）。
- 約 **47% 工具錯誤** 是「不該在這時調這個工具」，不是參數填錯。
- **機制**：SFT 學的是 **任務→工具關聯**，不是 **前置條件→工具** 的因果鏈；多數框架跳過 precondition 校驗。
- **後果**：步驟看似在「用工具」，整條鏈邏輯已錯。

**5. 反饋迴路信用分配**

- 長任務結果不符（例如超預算 2000）時，模型難判 **哪一步** 出錯 — 調整常改對留錯，越改越離譜。
- **機制**：強化學習的 **延遲獎勵** — 總獎勵難分配到單步 action。
- **後果**：「反思」變全局瞎改，準確率低。

### 本質三：五個工程對策（架構 > 換大模型）

| 困境 | 手段 | 要點 |
|------|------|------|
| 空間爆炸 | **分層規劃 + 領域剪枝** | 拆 ≤5 個一級子任務，每個 ≤3 條約束；子任務獨立規劃，狀態空間大幅縮小 |
| 隱式漏檢 | **約束圖譜 + 事後校驗** | 場景→隱式規則寫進知識庫；規劃完成後 **打回重規** 而非指望 LLM 懂常識 |
| 上下文衰減 | **注意力錨點** | 核心約束每 ~3 步 **重插** 到 context 前端 |
| 因果偏差 | **工具前置條件圖** | 調用前檢查 state 是否滿足；不滿足先跑前置任務 |
| 信用分配 | **單步獎勵 + 路徑回溯** | 每步對約束打分（±1）；只改負分步，不全盤重寫 |

- **7±2 原則**：每層子任務 ≤7、每子任務約束 ≤5 — 對齊工作記憶容量。
- **取捨**：Agent 規劃能力約 **七成靠架構、三成靠模型** — 架構到位，較小模型也能把失智率從 30%+ 壓到 **5% 以內**（文章 OTA 案例：複雜場景成功率 63%→96%）。
- **小公司**：不必一次建全量約束圖 — **先覆蓋最常見 20% 隱式場景** 即可消大部分漏檢。

### 本質四：框架不能代勞的部份

- LangGraph、AutoGPT 等只提供 **規劃腳手架** — 分層邏輯、約束校驗、工具前置、單步獎勵 **仍須自己實作**。
- 演進脈絡（簡）：ReAct → CoT/ToT → RAP → **分層因果規劃**；方向是 LLM 生成 + **符號推理／領域規則** +（未來）世界模型仿真 — 不是無限堆參數。

### 與 `4-熱門常用skills.md` 的關係

- Skills / Rules 解決 **單次 coding 任務的設計與驗收紀律**；本篇解決 **多步 Agent 執行鏈的中段邏輯崩**。
- 實務上：長 Agent 工作流應把 **約束圖譜、分層 plan、工具 precondition** 寫進 `CLAUDE.md` 或專用 skill，並與 `3-如何用claude-code-agentic工作流做AI代碼量化驗收.md` 的 **分 feature + 只讀 audit** 疊加 — 規劃對了，代碼驗收才有意義。

### 小結

- **問題**：多約束、多步 Agent 在關鍵節點邏輯錯 — 根因是規劃架構，不是「再換一個最強模型」。
- **手段**：分層剪枝、隱式約束顯性化、注意力錨點、工具因果校驗、單步信用分配。
- **結果**：把失智從結構性故障變成 **可測、可修、可迭代的工程問題**。
