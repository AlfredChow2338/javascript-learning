# `['1','2','3'].map(parseInt)` 為何是 `[1, NaN, NaN]`

`.map(parseInt)` 不是「把每個字串轉整數」，而是 **把 map 的三個參數原樣塞進 parseInt** — 第二個參數被當成 **radix（進位）**，不是 index。

### 本質：回呼簽名不一致

- **`Array.prototype.map`**：`(element, index, array) => …`
- **`parseInt(string, radix)`**：只用前兩個；radix 必須 2–36（或 0 表自動）

等同於：

```javascript
['1', '2', '3'].map((el, index) => parseInt(el, index))
// 0: parseInt('1', 0) → 1   （radix 0 當自動，'1' 合法）
// 1: parseInt('2', 1) → NaN （radix 1 非法）
// 2: parseInt('3', 2) → NaN （二進位無法解析 '3'）
```

### 正確寫法

```javascript
['1', '2', '3'].map(Number)
['1', '2', '3'].map((s) => parseInt(s, 10))
```

### 小結

- **問題**：高階函數直接傳 `parseInt` 會參數錯位。
- **手段**：包一層只傳 element，或改用 `Number`。
- **結果**：`[1, 2, 3]`。
